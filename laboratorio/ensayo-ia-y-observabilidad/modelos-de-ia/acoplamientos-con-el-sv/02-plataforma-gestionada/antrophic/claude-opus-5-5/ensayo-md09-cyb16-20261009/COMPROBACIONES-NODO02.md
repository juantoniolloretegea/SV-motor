# Nodo 02 · condiciones efectivamente comprobadas

Corte de recepción de MD01-R0, 09/10/2026. Este nodo se destina exclusivamente a experimentación. No se declara aptitud clínica, aprobación científica del candidato ni recepción independiente.

| Aspecto | Evidencia y alcance |
|---|---|
| Modalidad | Cuaderno Kaggle como soporte; inferencia remota mediante Model Proxy/Benchmarks. Los pesos de Claude no están alojados en el cuaderno. Región, hardware del proveedor y revisión inmutable de pesos no comunicados. |
| Identidad | La respuesta HTTP 200 declaró `anthropic/claude-opus-5-5@default`. `default` es un alias mutable; no identifica una revisión fija de los pesos. |
| Suministro | MCP mdBook Rust: manual, cuatro documentos y 31 secciones; ciberseguridad, cinco documentos y 28 secciones. Diarios completos y aislamiento cotejados antes de inferir. El control entrega el corpus íntegro; no se atribuye navegación autónoma al candidato. |
| Paquete | SHA-256 `758b9bac230b81410df73795c7c74ae3089987bfb8aecc7d53917c50896f749d`. Preguntas, revisiones, capítulos y fragmentos fijados antes de la primera solicitud. Claves, criticidades y adjudicación fuera del contexto. |
| Política y licencia | Constan literalmente en el contrato efectivamente enviado, conservado junto con su huella. El cotejo de recuperación exige identidad íntegra de contrato y petición. No se modifica el núcleo, su semántica ni su IR. |
| Control | Composición, decisiones, secuencia, guardas, recepción y medición en Rust. Los auxiliares del cuaderno sólo descargan, arrancan o recuperan archivos. No sustituyen al Director ni al Árbitro. |
| Frontera | Solicitud HTTP completa y respuesta original conservadas; HTTPS hacia el intermediario, sin redirecciones ni reintentos automáticos. La clave temporal se utiliza en memoria dentro de Kaggle y no se conserva. |
| Herramientas | No se ofrecen herramientas, navegación o búsqueda al candidato; la respuesta recibida no contiene llamadas a herramientas. Esto acredita la frontera observada y no demuestra el estado interno del proveedor. Internet del cuaderno permite transporte y recuperación autorizados; no equivale a navegación del candidato. |
| Separación | El candidato recibe textos y su propia historia; no dispone de una herramienta que modifique corpus, claves, adjudicación, diarios o telemetría. Los originales quedan bajo el control del ejecutor Rust y del repositorio. No se afirma aislamiento de procesos internos del proveedor. |
| Configuración | Razón `high`, salida máxima solicitada de 16384 tokens, JSON completo sin transmisión incremental. El esquema íntegro permanece en las instrucciones, con validación posterior estricta en Rust. La omisión de `response_format` sigue la adaptación oficial de Kaggle para esquemas anidados. |
| Tiempo | Manual: cota original de 90 minutos, sin reiniciarla tras la pausa instrumental. La continuación calcula el margen desde el inicio original y se limita después por reloj monotónico. Ciberseguridad conserva su propia cota. Cada solicitud tiene límite de 300 segundos. |
| Consumo | MD01-R0: 30330 tokens de entrada, 6713 de salida, total 37043; 1695 tokens de razonamiento incluidos. Coste comunicado: 255580000 nanodólares. El intento HTTP 400 no tiene contadores; su reserva completa, 606024000 nanodólares, permanece retenida. No se sustituye ese desconocido por cero. |
| Telemetría original | Proceso Rust inscrito, identidad y proceso padre, CPU, memoria, E/S y conexiones TCP/UDP filtradas por PID. MD01-R0: 203 muestras, 207 registros encadenados, cero fallos y máximo de 260 ms. No es inventario general del cuaderno. |
| Revisión r2 | Incorpora cantidades de hilos y descriptores, e identidad del espacio de red del proceso propio cuando Linux permite leerlas mediante `/proc`. No se leen destinos de descriptores, archivos privados ni entornos. R0 conserva su carencia original; no se repite para completarla. Handles y magnitudes no disponibles permanecen `null`. |
| Observabilidad del proveedor | No se observan su CPU, GPU, memoria, hilos, tareas, red o procesos internos. Sus contadores de uso se separan de la declaración operativa del candidato y de las mediciones externas. |
| Razonamiento | No se emitió texto de razonamiento en MD01-R0, aunque se comunicó su contador. Se conserva todo lo emitido sin reconstruir lo ausente. La explicación pública y el informe operativo no prueban introspección del sistema. |
| Primer byte | 52246 ms en MD01-R0; duración externa registrada 52356 ms y latencia del servicio 52033 ms. No son mediciones de primer token. La respuesta no es incremental. |
| Recuperación | El campo `refusal` vacío fue clasificado erróneamente como negativa. El original se recupera sin otra generación: cuerpo SHA-256 `1a7752ea04e53b7d2676478a1395505d4c895b24ddde68740f14ff11745daa75`, contrato y petición idénticos, diario correlacionado y 19 citas formalmente cotejadas. No se sustituye la respuesta ni se selecciona una mejor. |
| Comparabilidad | Deben declararse la plataforma gestionada, el alias mutable, la configuración de salida/razonamiento, la pausa propia, las revisiones instrumentales y las limitaciones de observación. El cotejo formal no adjudica suficiencia científica. R2 del banco sigue siendo la etapa final; no se elige retrospectivamente una etapa. |
| Custodia | Evidencias científicas en la carpeta del modelo; registro individual de mediciones y consumos en la sede administrativa privada, con recuperación por revisión y SHA-256. Main se comprueba de nuevo antes de cada publicación; se preservan incorporaciones concurrentes. |

La primera solicitud recibida utilizó el binario r1, SHA-256 `0244981796fcfe352e379d342c13056a16542b4e804b0cda74811e8a21f8af18`. Los ejecutables posteriores se identifican por sus propios recibos; compilar un componente no acredita que se haya utilizado en una solicitud. Los originales históricos, el resultado asistido y la recepción independiente pendiente conservan estados distintos.
